# A6U01 — Cost/Sell/Fee/Kit Characterization Scenario Catalog (T055)

**Scope:** the "follow-on work" T010's `scenario-catalog.md` explicitly deferred once T007
(`docs/rules/cost-selection-rules.md`), T008 (`docs/rules/sell-selection-rules.md`), and T009
(`docs/rules/fees-and-adjustments.md`) existed. This document is the sanitized characterization
fixture set for the cost, sell, rebate, fee, and kit decision paths those three documents extract —
input conditions, expected decision path, and expected critical outputs, each traced to a specific
rule ID, per T055's acceptance criteria and the constitution's requirement that "a matching final
price does not excuse a different decision path."

**This document does NOT replace `docs/characterization/scenario-catalog.md` (T010)** — that
document's 17 date/rounding/illustrative-fee scenarios remain the authoritative source for the
date-selection and rounding mechanisms; this document cross-references rather than duplicates them.

---

## Read this before using any scenario below for T056 or any other purpose

**Every expected output in this document was derived by hand-applying the formula already
documented (and source-cited) in `cost-selection-rules.md`/`sell-selection-rules.md`/
`fees-and-adjustments.md`/`kit-processing.md`/`kit-decision-table.md` — none of it was captured
from a live COBOL run, because no DB2/CICS/COBOL execution environment has been available to this
project at any point (the standing blocker recorded in every document in this set).**

This is exactly the distinction Codex's own G3 and G4 reviews (`docs/reviews/g3-cost-parity-review.md`,
`docs/reviews/g4-kit-parity-review.md`) drew a hard line on: *"self-authored expected values are
not independent COBOL parity evidence."* That statement is correct and applies in full to this
document. What this document *is*: the sanitized input/expected-output/expected-decision-path
fixture set that T056's `ParityRunner` needs to exist before it can run anything — the "expected"
column of a comparison that has not yet happened. What this document *is not*: proof that COBOL
actually produces these values. Closing that gap requires either a live COMMAREA capture or an
actual COBOL execution adapter, neither of which exists yet (same blocker recorded against T018's
ASSUMPTION and every rounding/tie-boundary scenario in T010's catalog).

**Confidence key** (same as every other document in this set): CONFIRMED (decision path and/or
formula read directly from source), INFERRED (reasonable but unverified assumption in the
governing rule itself), BLOCKED (cannot be stated because the governing rule or a required input
is itself BLOCKED). A scenario's confidence describes the **rule's** evidence quality, not whether
this document's arithmetic was independently re-verified by a second method — where hand arithmetic
could introduce its own error, that is noted per scenario.
